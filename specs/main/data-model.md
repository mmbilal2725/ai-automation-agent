**Phase**: 1 Design Output

## Entities

### 1. Message (Inbound)

Represents a single inbound message from any channel.

```python
class Message(BaseModel):
    id: UUID                          # Internal message ID
    session_id: UUID                  # Links to Session
    channel: Literal["messenger", "instagram", "email"]
    sender_id: str                    # Channel-specific user/email ID
    content: str                      # Extracted text content
    raw_payload: dict                 # Original webhook payload (for audit)
    received_at: datetime
    correlation_id: UUID              # For tracing across logs
```

**Validation rules**:
- `content` must not be empty after stripping whitespace
- `channel` must be one of the three enum values
- `sender_id` must not be empty

---

### 2. Session

Tracks the full conversation context for one user on one channel.

```python
class Session(Base):
    id: UUID (PK)
    channel: str                      # "messenger" | "instagram" | "email"
    sender_id: str                    # Channel-specific user identifier
    status: str                       # "active" | "escalated" | "closed"
    message_history: JSONB            # List of {role, content} dicts
    created_at: datetime
    updated_at: datetime
    escalated_at: datetime | None
```

**Indexes**: `(channel, sender_id)` — used on every message to look up or create session
**State transitions**: `active` → `escalated` (one-way in v1) | `active` → `closed`

### 3. KnowledgeEntry (FAQ)

Stored in ChromaDB (vector store). Not a SQL table.

```python
# ChromaDB document format
{
    "id": "faq-001",
    "document": "Q: What are your shipping times?\nA: Standard shipping takes 3-5 business days.",
    "metadata": {
        "category": "shipping",
        "question": "What are your shipping times?",
        "answer": "Standard shipping takes 3-5 business days.",
        "source": "faq.csv"
    },
    "embedding": [...]   # Generated by text-embedding-3-small
}
```

**Loaded from**: `data/faq.csv` (columns: `category`, `question`, `answer`)
**Updated via**: `python -m app.scripts.load_knowledge` CLI command

---

### 4. EscalationEvent

Audit log of every human handoff.

```python
class EscalationEvent(Base):
    id: UUID (PK)
    session_id: UUID (FK → Session)
    trigger: str                      # "low_confidence" | "explicit_request" | "error"
    confidence_score: float | None    # AI confidence at time of escalation
    conversation_snapshot: JSONB      # Full message_history at escalation time
    created_at: datetime
    notified_at: datetime | None      # When human was actually notified
```

---

### 5. ChannelResponse (Outbound — optional audit log)

```python
class ChannelResponse(Base):
    id: UUID (PK)
    session_id: UUID (FK → Session)
    channel: str
    content: str
    sent_at: datetime
    status: str                       # "sent" | "failed"
    error: str | None
```

## Entity Relationships

```
Session (1) ────< Message (many)
Session (1) ────< EscalationEvent (many)
Session (1) ────< ChannelResponse (many)
KnowledgeEntry ── (ChromaDB, no FK relation)
```

---

## Message Flow (Unified Schema)

```
[Messenger Webhook]  ─┐
[Instagram Webhook]  ─┤──► normalize_message() ──► Message ──► AI Pipeline ──► ChannelResponse
[Email Webhook]      ─┘
```

The `normalize_message()` function is the key adapter — it converts any channel's raw payload into the unified `Message` schema. All downstream code only ever sees `Message`.
